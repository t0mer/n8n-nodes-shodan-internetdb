## 1. Project overview

An n8n community node package for **Shodan InternetDB** (`https://internetdb.shodan.io`),
Shodan's free, keyless IP lookup service. For a given IP it returns open ports,
CPEs, hostnames, tags, and known CVEs. The dataset is refreshed about once a week
and contains no banners.

**Goals**

- Action node **Shodan InternetDB**: look up one IP per item, or many IPs / CIDR
  ranges in one call, with clean output shaping for downstream nodes and AI agents.
- Trigger node **Shodan InternetDB Trigger**: polling trigger that watches a list
  of IPs/ranges and emits **only changes** (new/closed ports, new/resolved CVEs,
  tag and hostname changes). This is the attack-surface-monitoring use case.
- Zero runtime dependencies. No credentials required. MIT license. Published
  through GitHub Actions with provenance. Built to pass n8n Creator Portal verification.

**Non-goals (v1)**

- No full Shodan API (search, banners, scans, alerts). That needs an API key and
  is covered by other packages. Keep this package InternetDB-only.
- No DNS resolution inside the node. Users resolve hostnames upstream (n8n's DNS
  or HTTP nodes). Hostname input is rejected with a clear message (§6.2).
- No CVE enrichment (CVSS/EPSS/KEV). Output keeps CVE IDs only; a later version
  or a separate node can enrich.
- No persistent storage beyond the trigger's snapshots in workflow static data.

## 4. InternetDB API contract

**Source of truth:** `https://internetdb.shodan.io/openapi.json` (OpenAPI 3.0.2).
Save a copy at `tests/fixtures/openapi.json` and add a test that the `Host`
schema's required fields match the TypeScript type. If anything below conflicts
with the spec, the spec wins; flag it in the PR description.

### 4.1 Endpoint

| Method & path | Auth | Description |
|---|---|---|
| `GET https://internetdb.shodan.io/{ip}` | none | Open ports, vulns, and other info for an IP |

That is the **only** endpoint. Base URL is a constant in `shared/constants.ts`,
not a parameter.

### 4.2 `Host` response (200)

All six fields are required by the spec:

```ts
interface InternetDbHost {
  ip: string;
  ports: number[];
  cpes: string[];      // CPE 2.2 URIs, e.g. "cpe:/a:openbsd:openssh:7.4"
  hostnames: string[];
  tags: string[];      // e.g. "vpn", "cdn", "cloud", "self-signed", "eol-product"
  vulns: string[];     // CVE IDs, e.g. "CVE-2017-15906"
}
```

Example:

```json
{ "ip": "51.83.59.99", "ports": [22, 80, 443, 500],
  "cpes": ["cpe:/a:igor_sysoev:nginx", "cpe:/a:openbsd:openssh:7.4"],
  "hostnames": ["www.sampleresponse.fr"], "tags": ["vpn"], "vulns": ["CVE-2017-15906"] }
```

### 4.3 Non-200 responses (handle all of them)

| Status | Meaning | Handling |
|---|---|---|
| `404` | IP has no data in InternetDB (body `{"detail":"No information available"}`) | **Not an error by default.** See `noDataBehavior` (§6.3). |
| `422` | Validation error (bad IP string). Body is FastAPI `HTTPValidationError`. | `NodeOperationError` with the `detail[].msg` text. Should be rare because inputs are validated locally first. |
| `429` | Rate limited (limits are undocumented) | Retry with exponential backoff + jitter (§7). Honor `Retry-After` if present. |
| `5xx`, network error, timeout | Service problem | Retry per §7, then `NodeApiError`. |

Confirm the 404 body live during development (`curl -i https://internetdb.shodan.io/10.0.0.1`
or any unrouted public IP) and store it as `tests/fixtures/404.json`.

### 4.4 Facts to surface in the UI and README

- Free for **non-commercial** use. Commercial use requires a Shodan enterprise
  license. Put this in the node's `description` notice and in the README.
- Data refreshes about **weekly**. It is a snapshot, not a live scan.
- No banners and much less data than a full Shodan host lookup.
- Rate limits are not documented. The node defaults to polite behavior (§7).

## 6. Action node — Shodan InternetDB

`usableAsTool: true`. Lookups are read-only and are a natural AI-agent tool
("what's exposed on this IP?"). Give each operation a precise `action` string
and parameter descriptions written for an LLM reader.

Icon: `nodes/ShodanInternetDb/internetdb.svg` (original artwork, light/dark safe).
Codex category: `Development` + subcategory for security if the scaffold's codex
schema allows; otherwise `Utility`. `resources.primaryDocumentation` points to
the README on GitHub.

### 6.1 Resource: IP

**Lookup** (default operation)
- One lookup per input item.
- Parameters:
  - `ip`: string, required, placeholder `1.1.1.1`, supports expressions.
  - `outputMode` (see §6.4), default `host`.
  - Options collection (§6.3).
- Output: one item per input item (or several, depending on `outputMode`).

**Lookup Many**
- Takes a list of targets and runs all lookups in one node execution.
- Parameters:
  - `targets`: string, required. Accepts IPs and CIDR ranges separated by commas,
    whitespace, or newlines (e.g. `1.1.1.1, 8.8.8.0/30`). Supports expressions,
    so a user can pass `{{ $json.ips.join(',') }}`.
  - `runOnce`: boolean, default `true`. When true, the node reads `targets` from
    the first item only and runs once. When false, it runs per input item.
  - `outputMode`, default `host`.
  - Options collection (§6.3), plus:
    - `maxAddresses`: number, default 256, min 1, **hard max 4096**. The total
      expanded address count per execution. Over the limit → `NodeOperationError`
      that says how many addresses the input expanded to.
    - `concurrency`: number, default 1, min 1, max 5.
    - `delayMs`: number, default 250, min 0. Pause between requests per worker.
- De-duplicate expanded addresses before looking them up. Preserve input order
  in output.
- For CIDR, include network and broadcast addresses only for `/31` and `/32`
  (standard host-range semantics otherwise).

### 6.2 Input validation (`shared/ip.ts`, unit-tested)

- Accept IPv4 dotted-quad and IPv4 CIDR `/0`–`/32`. Reject leading zeros
  (`01.2.3.4`) to avoid octal ambiguity.
- IPv6: InternetDB's coverage is IPv4. Accept a single IPv6 address and pass it
  through (no CIDR expansion for IPv6). Treat a 404 per `noDataBehavior`.
- Hostnames/URLs: reject with *"InternetDB only accepts IP addresses. Resolve
  the hostname first (for example with the DNS node) and pass the IP."*
  Strip surrounding whitespace. Don't guess at other formats: `1.2.3.4:443` is
  invalid and gets a clear message.
- **Non-public ranges** (RFC1918, loopback, link-local, CGNAT `100.64/10`,
  multicast, reserved, `0.0.0.0/8`, broadcast, documentation ranges): these can
  never have data. Behavior controlled by `nonPublicBehavior` (§6.3). Never send
  them to the API.
- CIDR expansion is lazy (generator) and checks `maxAddresses` before any request.

### 6.3 Options (both operations)

| Option | Type | Default | Behavior |
|---|---|---|---|
| `noDataBehavior` | options | `returnEmpty` | On 404: `returnEmpty` → emit a host object with empty arrays and `found: false`; `skip` → emit nothing for that IP; `error` → throw `NodeOperationError`. |
| `nonPublicBehavior` | options | `skip` | For non-public IPs: `skip` → emit `{ ip, found: false, skipped: 'non_public' }` in `host` mode (nothing in other modes); `error` → throw. |
| `includeSummary` | boolean | `true` | Add derived fields (§6.5). |
| `includePortNames` | boolean | `false` | Add `services: [{ port, name }]` from a small static map of well-known ports in `shared/ports.ts` (IANA names, ~80 common entries). Unknown ports get `name: null`. |
| `timeoutMs` | number | 10000 | Per-request timeout. |
| `maxRetries` | number | 3 | For 429/5xx/network errors (§7). |

### 6.4 Output modes

| `outputMode` | Items emitted per IP |
|---|---|
| `host` (default) | One item: the host object + summary fields. |
| `ports` | One item per port: `{ ip, port, serviceName? }`. |
| `vulns` | One item per CVE: `{ ip, cve }`. IPs with no vulns emit nothing. |
| `raw` | One item: the exact API response (404 → per `noDataBehavior`), no derived fields. |

`pairedItem` must be correct in every mode, including Lookup Many with
`runOnce: true` (pair to item 0).

### 6.5 Derived fields (`includeSummary`)

Added to `host` mode items only:

```ts
{
  found: boolean,              // false on 404 (returnEmpty)
  portCount: number,
  vulnCount: number,
  hasVulns: boolean,
  hasEolProduct: boolean,      // tags includes "eol-product"
  lookedUpAt: string,          // ISO timestamp of this request
  source: 'shodan-internetdb'
}
```

Sort `ports` ascending and `vulns` by CVE year then number, so output is
stable and diff-friendly. Leave `cpes`, `hostnames`, `tags` in API order.

### 6.6 Errors

- Validation problems → `NodeOperationError` naming the offending input value
  and, for batches, its position.
- API problems after retries → `NodeApiError` with status and a human message.
- Support `continueOnFail()`: emit `{ ip, error, statusCode? }` for the failed
  IP and continue with the rest. In Lookup Many, one failed IP must not abort
  the batch when `continueOnFail()` is on.

## 7. HTTP client & rate limiting (`shared/client.ts`)

- Single function `lookup(ctx, ip, opts): Promise<LookupResult>` used by both nodes.
  `LookupResult = { status: 'found', host } | { status: 'not_found', ip }`.
- `httpRequest` with `returnFullResponse: true` and `ignoreHttpStatusErrors: true`
  so the client inspects status codes itself. `json: true`. Set a
  `User-Agent: n8n-nodes-shodan-internetdb/<version>` header (version read from a
  constant generated at build time or hard-coded and bumped with releases; **no
  file reads at runtime**).
- URL-encode the IP path segment (IPv6 colons).
- Retries: exponential backoff `500ms * 2^attempt` + up to 250ms jitter, capped
  at 10s. Use `Retry-After` (seconds) when present, capped at 60s.
  Retry only 429, 5xx, and network/timeouts. Never retry 404/422.
- Worker pool for `concurrency` implemented in-house (simple queue + N async
  workers). Apply `delayMs` between requests per worker.

## 8. Trigger node — Shodan InternetDB Trigger

Polling trigger (`polling: true`, `poll()` implementation).

### 8.1 Parameters

- `targets`: string, required. Same format and validation as Lookup Many.
- `maxAddresses`: default 256, hard max 1024 (lower than the action node because
  it runs unattended).
- `events`: multiOptions, default all:
  `portOpened`, `portClosed`, `vulnAdded`, `vulnResolved`, `tagsChanged`,
  `hostnamesChanged`, `cpesChanged`, `dataAppeared` (404 → found), `dataDisappeared`
  (found → 404).
- `emitMode`: `perChange` (default: one item per individual change) |
  `perHost` (one item per IP that changed, with a `changes` object).
- Options: `concurrency`, `delayMs`, `timeoutMs`, `maxRetries` as in §6.3.
- Node description notice: *"InternetDB updates about once a week. Polling more
  than once a day wastes requests; every 12–24 hours is recommended."*

### 8.2 State & diff (core logic, unit-test heavily — `shared/diff.ts`)

- State in `this.getWorkflowStaticData('node')`:
  ```ts
  {
    version: 1,
    targetsHash: string,             // hash of normalized target list
    snapshots: Record<string, {      // key: IP
      found: boolean,
      ports: number[], vulns: string[], tags: string[],
      hostnames: string[], cpes: string[],
      seenAt: string                 // ISO
    }>
  }
  ```
  Store sorted arrays only. No hashing library: `targetsHash` is a simple
  in-house string hash (e.g. FNV-1a) over the sorted, normalized target list.
- **First activation** (no state): fetch everything, store snapshots, emit
  **nothing**. Option `emitCurrentOnFirstRun` (default false) emits the current
  state as `perHost` items instead.
- **Targets edited:** snapshots for IPs no longer in the target list are
  dropped. New IPs are seeded silently (same as first activation, per IP).
- **Diff:** set difference per field. `portOpened`/`portClosed` per port,
  `vulnAdded`/`vulnResolved` per CVE, one event each for `tagsChanged`,
  `hostnamesChanged`, `cpesChanged` with `added[]` and `removed[]`.
- `perChange` item shape:
  `{ ip, event, value?, added?, removed?, previousSeenAt, detectedAt }`.
- `perHost` item shape:
  `{ ip, found, current: {…}, changes: { portsOpened[], portsClosed[], vulnsAdded[], vulnsResolved[], tags: {added, removed}, … }, previousSeenAt, detectedAt }`.
- Only emit events selected in `events`. State is always updated for all fields.
- **Failures:** if a lookup fails after retries, keep that IP's previous
  snapshot unchanged and continue with the others. If **every** lookup fails,
  throw so n8n shows the trigger error. Never write partial garbage into state.
- **Manual mode** (`this.getMode() === 'manual'`): don't read or write state.
  Look up at most the first 5 targets and return them as `perHost` items with
  empty `changes`, so the user sees sample data.
- Return `null` when nothing changed, as n8n requires.

## 10. Testing

- `vitest` as a **devDependency** only. CI never calls the real API.
- Unit tests (no network, mock `httpRequest`):
  - `ip`: valid/invalid IPv4, leading zeros, CIDR `/32 /31 /30 /24 /0` counts,
    lazy expansion stops at `maxAddresses`, every non-public range, IPv6 pass-through,
    hostname and `ip:port` rejection with the exact message.
  - `client`: 200, 404 → `not_found`, 422 → error with detail text, 429 with and
    without `Retry-After`, 5xx then success, retries exhausted, no retry on 404,
    concurrency never exceeds the limit (instrumented mock).
  - `output`: all four output modes × found / not-found × `noDataBehavior`;
    sorting of ports and CVEs (`CVE-2021-9999` before `CVE-2021-10000`);
    `pairedItem` correctness.
  - `diff`: first-run seeding, each event type, removed targets dropped, new
    targets seeded silently, failed lookup keeps old snapshot, all-fail throws,
    manual mode touches no state, `perChange` vs `perHost` shapes.
  - Schema test: fixture `openapi.json` `Host.required` equals the keys of
    `InternetDbHost`.
- Manual E2E: `npm run dev`, look up `1.1.1.1`, `8.8.8.8`, an unrouted public IP
  (404), `10.0.0.1` (non-public), and a `/28` range.
